# ADR 0047: Sanitised Markdown rendering in the frontend

- Status: accepted
- Date: 2026-09-30
- Source: #108 (companies pages), security note on #108 from the #73 / PR #130 review, ADR-0041

## Context

Several texts in Jofi are Markdown: a company's research notes (written by the user) and its profile
(generated by the AI, possibly quoting web pages), later contact notes, portal notes and decline
reasons. The profile is untrusted: text a web page smuggled into it must not run script, open a link to a
`javascript:` URL, or load anything. A remote image in particular leaks the user's IP address and works
as a tracking pixel, so no image may load at all. Plain text would be safe but loses the structure
(headings, lists, links) that makes notes and profiles readable.

## Decision

One `Markdown` component in `src/ui` renders every Markdown text, with:

- **react-markdown 10.1.0** (MIT, remarkjs; CommonMark via micromark, React elements, never
  `dangerouslySetInnerHTML`), with `skipHtml`: raw HTML in the Markdown is dropped, not rendered.
  Docs: https://github.com/remarkjs/react-markdown#readme (Security, Options; via Context7).
- **rehype-sanitize 6.0.0** (MIT, rehypejs; hast-util-sanitize) with our own strict schema
  (`MARKDOWN_SCHEMA`) as the safety net the react-markdown docs recommend: only text structure (`p`,
  headings, emphasis, `code`/`pre`, `blockquote`, lists, `hr`, `br`, `a`), only `href` (http, https,
  mailto) and `ol start` as attributes, `script`/`style` stripped with their content, no comments.
  **No `img`**: images are removed, not proxied. Docs: https://github.com/rehypejs/rehype-sanitize#readme.
- **Links:** `urlTransform` and the `a` component accept only absolute `http:`, `https:` and `mailto:`
  URLs (`safeHref`); anything else, relative URLs included (they would point into Jofi's own API), keeps
  its text but is no link. Links render as `ExternalLink`: new tab, `rel="noopener noreferrer nofollow"`.
- Headings in Markdown render two levels down (`#` → `h3`), below the page's section headings.
- No GFM (tables, task lists, autolinks of bare URLs) for now: fewer dependencies; add `remark-gfm`
  when a text needs it, keeping the schema strict.

Website and careers-page URLs are not Markdown: the server accepts only http(s) (ADR-0041), and the UI
renders them as `ExternalLink` with the same `rel`.

## Consequences

- One place decides what Markdown may do; features never render Markdown themselves. A Vitest suite
  (`src/ui/Markdown.test.tsx`) proves that script tags, `javascript:`/`data:`/relative links and remote,
  inline-HTML and reference-style images are dropped; the e2e suite renders a seeded AI profile with
  the same attacks on the real page.
- Users see no images in notes or profiles, and inline HTML shows as its plain text content. If images
  are ever wanted, they need a server-side proxy or local copies, never a direct remote load.
- A few dozen small MIT-licensed unified/micromark packages join the bundle (all pass the licence check).
